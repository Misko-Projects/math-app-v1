# Widget kit

Shared building blocks for the math widgets (U03, used by U04/U05). Widgets import from `../kit`;
workshops never do (they render `WidgetHost`, see `../README.md`). Everything uses the U01 tokens
in `theme.css` and the age-mode sizes (`--target-min` 80 px K / 64 px G1+, `--target-gap` 12 px).
No widget defines its own palette.

| Module | What it gives you |
|---|---|
| `sprites.tsx` | `ObjectSprite` (shell, fish, starfish, crab, leaf, stone, pebble, stick, plank, firefly, counter; unknown ids draw a pebble) in two group tones that differ in lightness as well as hue (a colour-b counter also carries an ink ring, so the two colours differ by a mark). `spriteNameKey(id)` → `ui.sprite.<id>` for labels and the spoken name. |
| `layout.ts` | Pure, deterministic layouts in cell units: `objectSetLayout(ObjectSet)` (line, array, circle, scatter from `layoutSeed`, ten-frames, dice tiles, groups on plates, distractors, `sizeVaries`) and `dotsLayout` for `dots` stimuli. Counted objects keep reading order, so object `i` is `obj-<i>`. |
| `ObjectSetView.tsx` | Draws a layout. Static by default (one `img`); pass `renderObject` to turn objects into tap or drag targets, and `cell`/`minCell` to keep them tap-sized. |
| `StimulusView.tsx`, `stimulusKinds.ts` | One renderer per `StimulusSpec` kind: objects, dots (incl. fingers), ten-frame, rekenrek, number line, number bond, expression (with `renderBlank`), groups, array, base ten, scene, `fraction` (`FractionView`), `chart` (`ChartView`), `shape` (`ShapeSetView`), `gauge` (`GaugeView`), `clock` (`ClockView`) and `coins` (`CoinsView`). The switch is exhaustive and `STIMULUS_KINDS` is typed over the union, so a new kind does not compile until it is listed; the kind still owed (bar model) is `placeholder` there and draws a neutral card. Read the table, not the source text, to learn what is drawn. A picture's accessible name is "Look at the picture", never the quantity asked for. |
| `ShapeView.tsx` (U05) | `ShapeView` / `ShapeSetView`: exact 2-D shapes and drawn solids from a `ShapeCard` (equal sides, right angles, `rotationDeg`, `scale`; open figures visibly open), with attribute marks (`markFor`). `shapeSetUnit` puts several pictures on one scale. |
| `GaugeView.tsx` (U05) | The `gauge` stimulus: a scale, thermometer, beaker or dial that reads exactly its `value` on evenly spaced ticks (`gaugeTicks`, `gaugeLabels`; numerals 32 px). |
| `LengthViews.tsx`, `SceneAnchors.tsx` (U05) | Measured objects, unit pictures and rulers drawn to one scale, and the anchors of a place-relative scene. |
| `BoxEntry.tsx` (U05) | `BoxEntry`: one or more typed answer boxes (a unit picture after the number) with the number pad, for answers that are several numbers or carry a unit; `enteredValues`. A single plain number after a manipulative uses `NumberEntry`. |
| `useAvailableSize.ts`, `useFlip.ts` (U05) | The measured widget area for the measurement and geometry layouts, and a FLIP move for re-ordered cards. |
| `FractionView.tsx`, `fractionShapes.ts` (U05) | The `fraction` stimulus: a circle, rect, bar (strip) or loaf cut into `parts` (1–12), the first `shaded` filled. Parts come from the engine's exact geometry (`fractionPicture`), so equal parts are equal to the pixel and unequal ones visibly unequal; filled = sea-deep fill with a solid outline, empty = dashed outline; cuts are two-tone lines. A whole's size depends only on its shape, so pictures compared side by side are one size. |
| `FractionEntry.tsx` (U05) | Typing a fraction: two boxes stacked as a fraction and a compact 4 × 3 pad that fits beside a picture in the 906 × 373 area; one box with a decimal point for decimals. Desktop digits, Backspace, ArrowUp/ArrowDown, Enter. |
| `ChartView.tsx`, `chartLayout.ts` (U05) | The `chart` stimulus: picture graphs, bar graphs either way, tally charts, tables and line plots, from pure geometry (`chartGeometry`, unit-tested: bars end on their values, exact symbol counts, numerals 32 px, gridlines at least 8 px apart). Every category shows its sprite and name. `FitPicture` lays a chart out in the measured box, so its numerals are never scaled below 32 px while the box is at least the layout's smallest size. A `chart` stimulus is a vertical bar graph of one or two categories (the shared schema refuses anything else, 03 §5.1); the other kinds are for the bar-graph formats. A box too small for a chart's marks makes the geometry bigger than the box (never marks outside the chart), and the caller scales the whole chart down. `widgetLabels` (the bar-graph widgets, whose names are bounded) prints category names in one label style, 24 px (28 px in kindergarten mode; `LABEL_FONT_PX`), on one line, in a label cell as wide as the longest name needs (`nameWidth`); a `chart` stimulus keeps the default 20 px label, which wraps. `names={false}` shows the pictures alone (a data board beside a named chart). |
| `Stepper.tsx` (U05) | A one-more / one-less counter with the number shown large between the keys: the kindergarten answer control where the 3 × 4 pad cannot fit the area (bar-graph-read), and the tile builder of growing patterns (pattern-extend). Each tap counts aloud. |
| `NumberLineView.tsx` | Fixed-pixel number line (numerals stay 32 px): ticks, an even label stride when crowded, marks, jump arcs; `children(scale)` draws widget overlays with `scale.x(value)`, `scale.value(x)` and `scale.lineY`. `numberLineViewScale(props)` returns the same scale outside the SVG, for HTML controls laid over the line (a draggable flag, a hopping critter). |
| `FitPicture.tsx` | `FitPicture`: a stimulus fitted to a measured box (cards, compare sides): countable pictures re-flow their cell (`countLayout`, `cellToFit`; a double ten-frame may stack), fixed-pixel ones (number line, base ten, expressions) are drawn at their size and scaled down as a whole (`Scaled`). `naturalPictureSize` gives the aspect a layout plans with. |
| `controls.tsx` | `CheckButton` (debounced 400 ms, icon-only in K; `compact`: icon-only and square in any mode, for a short room), `PickCard` and `NumeralTray` (picked = ink ring + check badge; demo highlight = `.ni-invite`), `NumberPadKeys` (3 × 4 with no empty cell: `. 0 ⌫` when decimals are allowed, else a wide 0 and ⌫; or `shape="4x3"` for a short room; keys `--pad-key`, default `--target-big`, digits `--pad-digit`; an invited key's ring is drawn inside it, 12 px clear of its neighbours; desktop digits/Backspace/Enter), `applyPadKey`/`padValue`, and demo helpers `useAlive`, `useDemoPause`. |
| `NumberEntry.tsx` | `NumberEntry`: the numeral answer that follows a manipulative (tenframe-fill and rekenrek `thenAsk` or `read`, number-bond blanks), on main's controls: a `NumeralTray` 0…max (max ≤ 20) in the `columns` the widget's layout chose (trayGrid rows), else `NumberPadKeys` with the entered number shown large (`compact` keys at --target-min for short areas, the number above or beside them). The widget renders its own Check. `entrySize`, `entryChoices`/`entryGroups` (tray widths first, then the pad) and `nextPadKey` for layouts and demos. A card's or key's invite ring sits inside it, 12 px clear of its neighbours. Traces `opt-<n>` / `key-<k>`. |
| `arrange.ts` | Pure layout arithmetic for a picture plus items: `arrangedSize(row / side / stack / column / split, main, items, gap)`, `overflow`, `firstFit`, `numeralTraySize`, `trayColumnChoices`. Widgets compute each candidate layout's size from the measured room and keep the first that fits. |
| `room.ts` | `useWidgetRoom(rootRef)`: the widget's measured room (`width`, and the height its host gives it or Infinity), for container-relative layouts that keep targets full size (06 §1, §4). |
| `motion.ts` | `flyFrom(el, fromRect, { ms, lift })`: FLIP flight along an arc on the CSS `translate` property (0 ms with reduced motion). Put it on a wrapper, never on a `useDragToTarget` item. |
| `commit.ts` | `useCommitBarrier()`: `await committed()` at the end of a demo `play`, so it resolves only after React committed the op's last state change (#85). |
| `flight.tsx` | `useFlight(rootRef)`: demo-mode flights. `fly(fromRect, toRect, node)` glides a copy inside the widget root and resolves when it lands (at once with reduced motion); render `layer` in the root. |
| `keyPress.ts` | `useOncePerKeyPress()`: `take()` lets an action run once per Enter or Space press (always for pointer and touch). For controls that hand the focus to each other (a build step's Next and the answer step's Back), so a held key's repeats never flip the steps back and forth. |
| `CoinArt.tsx`, `CoinsView.tsx` (U05) | Original US coins drawn to one scale (`CoinArt`, `quarterPx`: dime < penny < nickel < quarter; copper penny; reeded dime and quarter; shell, wave, star and sun faces) and dollar bills (`BillArt`); `useMoneySpeech` (a piece's name and value, totals, counting up), `moneyText` (`40¢`, `$1.35`); `CoinsView` is the `coins` stimulus. Styles in `money.css`. |
| `MoneyBoard.tsx` (U05) | The concrete purse-and-tray board of coin-pay and make-change: purse stacks showing exactly what is left, tray piles drawing every piece, drag / tap-to-place / keyboard through `useDragToTarget`; `MoneyTag` (a labelled amount). The tray holds `capacity` pieces (`TRAY_PIECES_MAX`, or `TRAY_NARROW_PIECES_MAX` on a narrow board); `moneyLayout.ts` squeezes its piles into two rows (one on a narrow board) with every piece showing 16 px, and a purse stack leans at most 6 px so the purse is one row. A chosen piece arms the other zone, whose lying pieces then let the tap through, so placing never picks one up. |
| `ClockView.tsx` (U05) | `ClockFace`: 60 ticks, numbers 1–12 and two geared hands from one time `t`; `DigitalClock`; `ClockView` is the `clock` stimulus; `clockHandAt` is the hand a press takes hold of (the one under the finger, else by zone). Styles in `clock.css`. |
| `PadEntry.tsx` (U05) | Typed boxes for the number pad (`usePadEntry`, `PadBoxView`): `exactDigits` boxes (cents, minutes) keep leading zeros and fill only when full. |
| `twoStep.tsx` (U04) | A manipulative followed by a typed answer, in two steps that each fit the widget's room (the 906 × 373 area is 319 px inside): **build** (the manipulative and Next) and **ask** (a static picture, the answer control, Back and Check). `useTwoStep(rootRef, { interactive, trace })` holds the step (Next and Back hand the focus on, once per key press, traced as `next` and `back`); `StepActions` draws the buttons (`compact`: icon-only, for a room under `COMPACT_ROOM_H`; measure them with `useActionSize`); `roomBox(useWidgetRoom(ref))` is the box to plan in and `buildRoom(room, button)` the build step's share of it; `planAsk({ ageMode, max, button, actions, room, pictureScore })` picks the answer control (numeral tray, pad, or the `Stepper` at kindergarten sizes; `control` for a widget's own, such as two choice cards), where the actions go (`aside`: under the entered number, beside the pad's keys) and the box left for the picture; `AskStep` and `AskEntry` render the plan. The build step's layout is the widget's own (see equal-share and equal-groups `layout.ts`). |
| `grab.ts` (U04) | `useGrabUnderFinger()`: a small draggable item with a larger hit area is drawn under the finger while it is pressed, so `useDragToTarget` (which snaps from the item's rendered centre) drops it where the finger lets go. |
| `fives.ts` (U04) | Grids of one-size countable things in fives: `fivesGrid` / `fivesCell` (rows of 5 or 10 with a wider gap between fives), `zoneGrid` / `zoneCell` (a container's places, in rows or columns of five), `itemGap`, `balancedRows`, `MIN_ITEM_PX` (20). |

**How an amount is written and said (all five time and money widgets).** One rule, `moneyText` and `useMoneySpeech`: under one dollar in cents with ¢ (`65¢`, "sixty-five cents"); one dollar and above in dollars with two decimals (`$1.00`, `$1.35`, "one dollar and thirty-five cents"). A price tag, a running total, a count-up line's ends and a spoken total all use it, so `65¢` and `$1.00` stand side by side on purpose. Tested in `money.test.ts`.

Each widget imports its own stylesheet next to its component (`./<format>.css`), so parallel
widget PRs never edit one shared CSS file.
