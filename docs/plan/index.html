An adaptive math adventure for K–8 (and beyond)

This plan covers a game your kids want to play that teaches the math they will meet in school. It works out what each child already knows, teaches the next thing they're ready for, and brings older skills back before they fade. It runs on their Fire tablets and in any web browser. It starts at kindergarten and 2nd grade, and the design supports K–8 and high school from day one.

Built from four parallel research tracks: math progression, teaching and adaptivity, gamification, and technology. The full research notes, with about 250 cited sources, are in the repo under docs/research/.
Update (17 Nov 2026): decisions locked, and the build spec is written You accepted the recommendations, with these changes:
  • Devices: the new Alexa/Kids Tablets (Android, Chrome) plus browsers. Fire OS is dropped.
  • Distribution: open source (MIT), self-hosted by each family.
  • Standards: Wisconsin's 2021 standards (a revision of Common Core) are tagged alongside Common Core codes.
  • Avatar: a character creator, plus "make me from a photo".
  • AI: runtime AI for feedback and error diagnosis.
Policy finding: Google's Gemini API terms bar use in any app "directed towards or … likely to be accessed by individuals under the age of 18". So Gemini TTS is used only at build time, to pre-render narration files (a reasonable reading of the terms, not yet confirmed by Google), and all runtime AI uses Claude. Image models bar editing photos of minors, so the photo becomes attributes for the in-game SVG avatar, not a generated likeness. The full build specs are in docs/spec/, and the 34-issue build plan and orchestrator prompt are in docs/build/ in the repo.

Recommendations at a glance

These are my recommendations in each area. Each one is explained below with its alternatives, and in §12 you can pick your own options and copy the result back to me.

Game frame

"Number Island": the siblings share an island, and each building is a workshop. Doing the math is how things get built. Residents are collectible number creatures who ask for things to be built.

Curriculum

A prerequisite graph of small skills. It is built from Common Core plus the Achieve the Core Coherence Map (CC0), with the K–2 order taken from research learning trajectories. Grade is a label, not a gate.

Teaching

Objects, then pictures, then symbols. Show a worked example before practice. Strategies come before memorized facts. Every session mixes in spaced review of older skills. A skill counts as mastered only when it is still right a week later.

Adaptive engine

A skill rating for each child that works from the first answer, with explicit rules for what counts as mastery. A spaced-review scheduler gives partial review credit to simpler skills, and a short placement game finds where each child is.

App technology

A TypeScript web app (React + Vite). Questions are built from ordinary web elements and drawings, with a game engine (PixiJS) loaded only for mini-games. Progress is saved on the device, so it works offline.

Backend & hosting

A small API on Cloudflare Workers syncs progress across devices and serves the parent dashboard. Hosting should cost about $0 a month. Progress is stored as a list of answers that only grows, so syncing never has to resolve conflicts.

Getting it on the Fire

Add the web app's address to the allowed websites in each kid's Amazon Kids profile, with no sideloading. An Android app wrapper (Capacitor) stays ready if we ever want an app store.

AI (Claude)

Use Claude at build time only: it drafts problems, hints and voice scripts, code checks every answer, and you review before anything ships. The kids never chat with an AI.

First scope

Build K–3 (about 300 skills, enough headroom for both kids) on a structure that already covers K–8 and high school. Grades 4–5, then 6–8, follow as new workshops on the same island.

1What the math progression should look like

School standards are too coarse to adapt to: one Common Core standard usually contains 3 to 8 skills that need checking separately. Successful adaptive products (Math Academy, ALEKS) all use a graph of small skills with prerequisite links. We should do the same, with each skill taking about 5–15 minutes to teach and able to be practised with generated problems.

Backbone sources

  • Common Core (CCSS-M) K–8 domains plus the high-school categories, about 230 standards. We store only the codes, not the text, which has a restrictive license.
  • Achieve the Core Coherence Map: standard-to-standard prerequisite links, released as CC0 (no restrictions). Learning Commons distributes it as JSON with an API.
  • Progressions documents (CC BY): give us ready-made problem types, such as the 15 kinds of add/subtract word problem.
  • Clements & Sarama learning trajectories: the research-based order for K–2 counting, subitizing and composing numbers. We use their ordering and ideas, not their text.

How big is it?

  • Khan Academy uses about 140 skills per grade, IXL about 350, and Math Academy about 2,500 topics from grade 4 to university.
  • Our target is 80–150 skills per grade, or about 250–350 for K–3 in the first version.
  • K–8 comes to roughly 1,000 skills, and high school can be added as more strands on the same graph.

Data model (per skill)

Where each kid probably starts, and where to push

🐣 Advanced kindergartner

  • Firm up seeing and splitting numbers to 10 and 20 (ten-frames, 7 = 5 + 2, teens = 10 + n). Kids who count well often skip this step.
  • Then counting on → doubles → make ten, and "=" as "the same as".
  • Then tens and ones, adding within 100, telling time to the half hour, halves and quarters, and measuring length.
  • A realistic stretch goal is end-of-1st-grade math plus some 2nd-grade place value. Hold off on written methods like carrying until mental strategies are solid.

🦊 Advanced 2nd grader

  • Check that facts within 20 are fluent and that she understands regrouping in 3-digit add/subtract.
  • Then multiplication and division as equal groups, arrays and area, then break-apart fact strategies (7×6 = 5×6 + 2×6), then fact fluency.
  • Fractions on the number line are the single most valuable push. Then area and perimeter, time to the minute, and rounding.
  • Enrichment: puzzles in the style of Beast Academy, balance-scale equations with unknowns, and negative numbers informally ("below zero").

2The best teaching approaches

The strongest research reviews agree. The What Works Clearinghouse and IES practice guides, cognitive load research, and studies on retrieval and spacing all point to explicit teaching with visual models, then lots of spaced, mixed retrieval practice.

Advanced kids skip steps automatically: once a child shows they know the material, worked examples stop helping, so a quick "test out" check comes first. Open-ended problem-solving was weaker than direct teaching for grades 2–5 in Kapur's meta-analysis, so puzzles and productive struggle serve as enrichment on skills already mastered.

Objects → pictures → symbols

Every skill moves from objects (ten-frames, base-ten blocks, fraction bars) to pictures to symbols, and drops back a level when errors appear. Keep the objects visually plain; decorative ones distract. The number line appears everywhere (the WWC rates the evidence for it as strong).

Strategies before speed

Make ten, doubles, near-doubles and "think addition" are skills in the graph and must be learned before fact drills. Response speed is recorded silently. Kindergartners never see a timer; for the 2nd grader, timed games are an optional "beat your own best".

Retrieval, spacing, mixing

These have the strongest evidence of anything here. In a randomized 7th-grade study, mixing problem types beat practising one type at a time on a test a month later (61% vs 38%). Every session mixes old and new skills.

Aim for about 85% success

Engagement peaked near 90% success in a number-line game, and theory puts the best learning rate near 85%. Target 80–85% first-try accuracy for the 2nd grader and 85–90% for the kindergartner.

Feedback that teaches

Immediate, specific feedback, with hints that get gradually more helpful. Praise the strategy ("you made a ten first!"), never "you're smart". No lives, game-overs or negative points.

Catch misconceptions

Kids type, drag or tap their answers rather than picking from choices. Each problem type predicts common wrong answers, such as subtracting the smaller digit from the larger or forgetting to carry. When the same mistake repeats, the app re-teaches that skill and alerts the parent.

What "mastered" means

🔒 LockedA prerequisite isn't solid yet
🌱 LearningWorking through the lesson
💪 Practiced5 of the last 6 right, in at least 2 formats, over at least 2 sessions
⚡ FluentFact skills only: fast median response time
⭐ MasteredStill right when reviewed 1 day and 1 week later

A skill that fails two reviews in a row drops back a level. Each level comes with "why we think so" evidence on the parent dashboard.

Designing for a 5-year-old

Audio first. Every prompt is spoken, with a replay button. Almost no reading needed.
Big targets. At least 2 cm (about 80 CSS px). Tapping to place works as well as dragging, items snap into place, and a mis-drop costs nothing.
Short sessions. 5–10 minutes for K and 10–20 for 2nd grade, with a natural ending ritual.
Detect frustration. Repeated errors or quick taps bring an easier problem, a hint, or a break.

3The adaptive engine: options

With only two learners there is no data to train a statistical model. The engine has to work well from the first answer and be easy to explain to a parent. Every option below logs every attempt from day one behind a swappable interface, so we can upgrade later and replay the history.

Recommended

A. Skill rating + mastery rules + spaced review

An Elo-style rating per child per skill (the system used to rate chess players). Each problem's difficulty comes from its parameters, such as how many digits or how many regroupings. Explicit rules decide mastery, and a simplified version of Math Academy's review scheduler handles spaced review, including partial credit for easier skills.

  • Works from the very first answer
  • Uses the difficulty we already know for generated problems
  • Every decision is explainable ("5 of the last 6 right")
  • Simple to build and test
  • The weights are hand-tuned at first
  • Not a "true" probability of knowing the skill (we can add one as a second opinion)
Alternative

B. Bayesian Knowledge Tracing (BKT)

The classic intelligent-tutor model: each skill has a probability that the child knows it, updated after every answer.

  • Easy to read: "87% likely she knows this"
  • Well studied
  • Ignores problem difficulty
  • Its settings normally need data from many learners
  • No forgetting unless extended

Could run in the background alongside option A to give the parent dashboard a second opinion.

Alternative

C. Simple level ladder

IXL-style: each skill has levels, and N correct in a row moves the child up. No spaced review across skills.

  • Simplest to build
  • Predictable
  • No retention, so skills fade
  • Slow placement
  • Not truly adaptive across the graph
Upgrade path (option A) v1 is the rating plus rules. v2, once there is data from more families: fit better models (BKT with forgetting, or PFA) offline and compare their predictions. v3: tune the review scheduler (FSRS) on our own logs. v4, only at thousands of learners: heavier statistical models. Skip deep-learning knowledge tracing: simpler extended models match it, and it needs far more learners than we will have.

Placement: a short game that finds where each child is

The placement game picks questions along the graph. A correct answer raises confidence in everything that skill depends on. A wrong answer lowers confidence in everything built on it, and the next question checks a prerequisite. One question therefore updates many skills; Math Academy reports this cuts the number of questions about tenfold. Skills inferred this way are marked "assumed" and checked quietly during week one. There is always a "I haven't learned this yet" button, so nobody has to guess.

Kindergartner: 3–4 mini-games of about 5 minutes ("help the robot count"), with no fail sounds. It stops after two "I don't know"s in a row.
2nd grader: 2–3 sessions of about 10 minutes, including questions above grade level. A parent can say "she's doing 3rd-grade work at home" to start higher.

4Game design: three frames to choose from

The most important finding: put the math inside the main game action. Habgood & Ainsworth's Zombie Division study compared a game where you defeat enemies by dividing correctly against the same game with quizzes between levels. Kids learned more from the first version, and when free to choose they played it about 7 times longer. Prodigy is the cautionary tale: math is a toll gate before the fun. One advocacy group counted 4 math problems against 16 membership ads in 19 minutes (Prodigy disputes the count). All three frames below share the same learning engine. They differ in why kids come back.

Option A

🐾 Number Creatures

A world-map adventure. Creatures' bodies are quantities: a "7" has 7 segments, and a "½" creature splits in two. Kids befriend creatures by solving their puzzles. Creatures combine (3 + 4 → 7) and gain abilities, so the Ten-Whale lets you "make ten" anywhere.

  • Collecting is extremely motivating at ages 5–9
  • Combining creatures is addition
  • The map path doubles as a number line
  • Risks drifting into Prodigy-style battles
  • Older kids may find it babyish
  • Lots of art per creature
  • Completionist compulsion
Recommended · Option B

🏝️ Number Island

The siblings share an island that starts as a sandbar. Every building is a workshop whose mini-game is the math. The bakery makes bread by composing ten. The brick factory fuses 10 bricks into a rod. The garden plants arrays. The market makes change. The main road is a numbered path from 1 to 100 that the boat counts out loud. Number-creature residents move in and ask for things to be built.

  • Scales best to grade 8 (area, money, ratios, percents, coordinates, functions)
  • Real choice: what to build and how to decorate
  • A shared sibling island makes co-op natural
  • A persistent world gives a reason to return without streak guilt
  • Each workshop is a self-contained module, easy to add
  • An economy can turn into grinding: materials must be the direct product of the math
  • Fewer adrenaline moments, offset by storm and festival "boss" events
  • Free decorating time has to be capped
Option C

📖 The Lost Numbers

A voiced, episodic story: help a character restore a world whose numbers went missing. Each chapter unlocks an arcade cabinet mini-game (Firefly Count, Fraction Slicer, Balance Cargo…) that can be replayed for stars.

  • Lots of variety and novelty
  • Each mini-game can be built and tested independently
  • Great for short sessions
  • Story is expensive to write and voice, and it is linear (two kids need separate progress)
  • Risks becoming a collection of drills
  • Chasing high scores rewards speed over understanding

5Making it interactive: the math is the controls

Virtual manipulatives such as ten-frames, base-ten blocks and fraction bars show a moderate positive effect (about 0.34 SD), better than games in general (0.1–0.3). Linear numbered board games improve young children's number sense; circular boards with the same numbers don't (Siegler & Ramani). So the manipulatives are the input, and the world map is a number line.

6Healthy engagement: hard rules

Radesky et al. (2022) found manipulative design in apps used by nearly all the young children in their study. We will make kids want to come back without the tricks.

✅ Do

  • Give choice (what to build, where to go, how to decorate), a sense of getting better (visible mastery, the right level of challenge), and connection (sibling co-op, parent gifts, residents who care). These three needs predict enjoyment and continued play.
  • Praise that gives information, and surprise rewards. Use cosmetics and new abilities, not pay-per-problem.
  • Weekly goals for young kids. Streaks only ever add up and are never lost.
  • A parent "visitor" who can leave a surprise gift, plus real-world milestones the parent defines.
  • Optional family quiz night, with each player getting questions at their own level.

🚫 Never

  • Ads, loot boxes, paid currency, or upsells aimed at kids.
  • Lives lost for mistakes, game-overs, or negative points.
  • Countdown timers for young kids by default, or public speed leaderboards.
  • Guilt notifications, limited-time pressure, or streak shaming.
  • Rewards that are expected and handed out per task. These undermine kids' own interest (the overjustification effect).
  • Answering a question on one screen to earn a turn at the "real" game on another.

7Recommended system architecture

The design separates content (data), engine (pure logic) and presentation (the island and widgets). That gives three things: K–8 and high school can be added by writing content rather than rewriting code, the engine can be tested without a browser, and a different front end (say a game engine) could reuse the same engine later.

8Technology options

Most of this app is interactive math screens (number lines, ten-frames, drag and drop) with a few arcade-style mini-games. It has to load fast on a slow Fire 7 and be built quickly with AI coding agents. Versions below were checked in November 2026.

App framework

Recommended

A. TypeScript web app

React 19 + Vite + vite-plugin-pwa. Question screens use ordinary web elements and drawings (DOM/SVG/CSS); PixiJS v8 (or Phaser 4) loads only for mini-games; Rive animates the mascot. Capacitor 8 can wrap it as an Android app later.

  • Smallest download (well under 1 MB of code before mini-games)
  • Best performance on low-end Fires for screens like these
  • One codebase for web, Fire and Android
  • Best accessibility and automated testing
  • Best AI-agent productivity (TypeScript)
  • A rich game-world feel takes deliberate work
  • Two rendering approaches to integrate (DOM and canvas)
  • On Fire it runs inside Silk, not as a true installed app

Fire risk: low–medium.

Alternative

B. Godot 4.6 game engine

A real game engine (GDScript), with web export and a native Android app.

  • Best game feel: scenes, particles, physics
  • The native Android build runs well on Fire
  • Free and open source
  • 5–10 MB+ web download; slow in Silk on a Fire 7
  • Weak text, UI and accessibility
  • The parent dashboard needs a separate web app anyway
  • AI agents struggle with its editor scene files

Fire risk: medium (sideloaded apps are flaky in child profiles).

Alternative

C. Flutter 3.47 (or Expo / React Native)

A native-first framework with a web build.

  • High-quality native Android app for Fire and the new Alexa tablets
  • Good animation and widget tests
  • Expo shares React/TypeScript skills
  • Flutter's web build is heavy (1.5–3 MB+ engine) and slow on low-end Silk
  • Many plugins assume Google services, which Fire lacks
  • Expo's web output has gaps compared with native

Fire risk: medium on web, low as a native app.

Getting it onto the kids' tablets

RecKids Browser allow-list

In each child's Amazon Kids profile, add the app's URL to the approved websites and bookmark it. No sideloading, and updates arrive instantly. It also works on any new tablet, laptop or iPad.

LaterAmazon Appstore (Capacitor)

The cleanest native path for Fire child profiles. Kids apps go through store review and COPPA requirements.

LaterGoogle Play

For the new Alexa and Kids Tablets and other Android devices. Play's Families policy applies, and the parent approves each download on Kids Tablets.

AvoidSideloaded APK

Often doesn't appear or update properly in child profiles. Fine only as a developer test.

Other building blocks

Kid sign-in. Only the parent has an account (magic link or passkey). Each device is paired once with a code. Kids tap their avatar and pick 3 of 9 pictures, which keeps siblings out of each other's profiles but is not real security. A parent gate guards settings. Kids never need an email address.
Voice. Pre-render all narration at build time with a high-quality TTS voice, then stitch clips together at runtime. Don't rely on the browser's built-in speech, which Fire OS may block. Optional idea: record a parent's voice for praise lines.
Content as data. Skills and problem templates live as YAML in the repo, validated by Zod. Problems are generated from seeded random numbers, so any problem can be reproduced exactly. Property tests check that generators never produce invalid problems.
Testing. Vitest 4 for the engine, fast-check property tests for generators, Playwright with a Fire-sized mobile viewport, Storybook for widgets, and GitHub Actions to run it all. Performance budgets checked in CI.
Privacy (COPPA). The amended rule has been fully in force since 22 Apr 2026. No third-party analytics or ad SDKs, all assets self-hosted, no voice or photo capture, and a written data-retention policy. This matters once the app is shared beyond your family.
Performance budget. Under about 2–3 MB total for the first load, one WebGL canvas at a time, animations that still look good at 30 fps, and capped device pixel ratio on low-end Fires.

9Where AI (Claude) fits

Recommended for v1

Build-time content only

Claude drafts problem templates, word-problem wording, hint ladders, misconception explanations and voice scripts. Code computes every answer, automated checks run, and a person reviews each PR. The content ships as static files, and the child never talks to the model.

  • Safe, and no children's data reaches a third party
  • Lots of content authored quickly
  • Works offline
Later, optional

Guarded runtime hints

Runtime calls send only structured inputs (skill, problem, the wrong answer) with no personal data. The model chooses from vetted hint templates or its output is validated. Requires an AI disclosure and parental consent, and must follow Anthropic's guidelines for products serving minors.

  • In Bastani et al. (2025), students given unguarded GPT-4 did 17% worse on later exams without it; guardrails largely removed the harm
  • Cost, latency, and COPPA rules on sharing with third parties
Alternative

No AI at all

Hand-write every template. Simplest to reason about, but much slower to cover K–8.

10Roadmap

These are milestones rather than dates. Each one leaves the kids with something playable or answers a real question.

M0

Device check + skeleton

Run a one-page test on the kids' actual Fires, in both Silk and the Kids Browser: offline support, local storage surviving a reboot, audio unlock, WebGL frame rate, home-screen behaviour. Set up the monorepo, CI, Zod schemas and a graph validator. Exit: we know the web app works in a child profile.

M1

Engine + first content

Skill graph for counting, subitizing, composing, add/sub, place value and early multiplication (about 120 skills). Seeded generators with property tests, the skill rating, mastery rules, the review scheduler and the placement algorithm. Core widgets: number pad, ten-frame, dot flash, number line, base-ten blocks. Exit: a plain practice mode that both kids can use and that adapts.

M2

Number Island MVP

Island hub, profiles with picture passwords, the placement mini-games, and 5–6 workshops: Numbered Road, Firefly Count, Ten-Boat, Brick Factory, Garden Arrays, Market. Voice narration, celebrations, offline play, session wind-down. Exit: the kids choose to play it, measured by math share, return rate and accuracy.

M3

Parents + sync

Cloudflare API, parent sign-in, device pairing, syncing the answer log, and a parent dashboard: skill map with evidence, misconception alerts, time caps, surprise gifts. Shared island projects for both kids. Exit: progress is shared between tablet and laptop.

M4

Through grade 3, then 4–5

Fractions bakery, Clock Dock, area plots, division fish-sharing, Puzzle Tower, Rhythm Harvest fact fluency. Build-time Claude drafting pipeline to scale content. Then grades 4–5: multi-digit ×/÷, decimals and coordinates.

M5

Grades 6–8 and beyond

Ratios, rates, percents, integers, equations and functions, as the island becomes a town economy. Optional Capacitor app for the Appstore or Play, and COPPA readiness if shared publicly. High-school strands on the same graph.
